# AGENTS.md

Guidance for AI agents working in this repository.

## What this repo is

**Lectrix themes for calibre**: Lectrix's light and dark themes for the calibre e-book manager, shipped as two calibre plugins and a palette file. The colors come from Lectrix's design tokens (`lectrix/src/app.css` in the sibling Lectrix repo), which are Neo's light and Midnight themes for Obsidian tinted toward Lectrix blue.

The folder is still called `calibre-proper-dark`, the project's old name. The GitHub repo is `pan4ratte/calibre-lectrix-themes`. The old name lives on only in the settings migration (`MAIN_PREFS` and `EDITOR_PREFS` in `src/chrome.py`), which must stay.

| Part | Files | Notes |
|---|---|---|
| Colors and styles | `src/lectrix_theme.py` | Every color, the palette, the Qt stylesheets, the title bar colors and the editor syntax themes. Pure Python, no calibre or Qt imports. |
| Shared styling | `src/chrome.py` | What the palette can't reach: Windows title bars, the app stylesheet, the side panels' edges, the Tag browser's hover, lists' current cell, the Preferences cards. |
| Main plugin | `src/main_plugin/` | "Lectrix themes", an `InterfaceAction` plugin whose toolbar button switches between light and dark (calibre's `color_palette`), with a menu for the rest. Sets calibre's palettes, installs the styling, has the on/off setting. The button's icon is `images/icon.png`, Lectrix's 256 px Yaru icon (`lectrix/design/yaru/apps/square`). |
| Editor plugin | `src/editor_plugin/` | "Lectrix themes for Edit book", an `EditBookToolPlugin`. Installs the styling in the editor and writes and picks the Lectrix syntax themes. |
| Font | `src/fonts/`, `tools/subset_fonts.py` | Google Sans Text 14.000, regular, italic, bold and bold italic, cut down to Latin, Greek and Cyrillic without the Google logo ligatures, with its `OFL.txt`. Made from the official release by `tools/subset_fonts.py` (needs fontTools, only to run it), and tracked. `build.py` puts it in both zips; `chrome.py` loads it and makes it the interface font. |
| Palette file | `lectrix.calibre-palette` | Generated by `build.py`, tracked, and attached to releases. Never edit by hand. |
| Build | `build.py` | Writes the palette file and `dist/*.zip`. |

Needs calibre 7 or newer. The title bar colors are Windows 11 only.

## How it fits together

- **One source of colors.** All colors are in `TOKENS` and `BLENDS` in `src/lectrix_theme.py`. `BLENDS` holds colors CSS gets from `color-mix()` or opacity, worked out ahead of time because Qt has neither. Change a color there and nowhere else.
- **Shared modules are copied.** `build.py` puts a copy of `lectrix_theme.py` and `chrome.py` in each plugin zip, so inside a plugin they are imported relatively (`from .chrome import ...`) or as `calibre_plugins.<import name>.chrome`. The import names are `lectrix_themes` and `lectrix_themes_editor`.
- **The palette is applied once.** `palette_version()` is a hash of the palette colors. The main plugin applies the palettes when the stored version differs, so a user's edits in Adjust colors survive until an update changes the colors. The palettes found first are backed up and restored when the theme is turned off.
- **The editor runs as its own program.** It reads the main plugin's on/off setting from disk each time (`theme_enabled()`), since the main plugin isn't loaded there.
- **Mode changes go through `palette_changed`.** calibre resets its app stylesheet on every palette change and then emits `app.palette_changed`. `chrome.py` appends its stylesheet after `SEPARATOR` on that signal, and restyles title bars. To apply a setting change at once, emit the signal (`restyle()`).
- **Turning the theme off undoes everything**: palettes, stylesheet, title bars, the current-cell property, the Preferences cards' size, the interface font and, at its next start, the editor's syntax theme. Anything new must be undone the same way.
- **calibre's own widget classes can be styled by name.** Qt stylesheet type selectors match PyQt class names, so the stylesheet targets calibre widgets such as `BooksView` (the book list), `TagsView` (the Tag browser), `BookInfo` (Book details) and `Browser Category` (the Preferences page) directly.
- **calibre internals are patched with care.** `patch_tree_hover`, `patch_panel_edges` and `patch_preference_tiles` wrap calibre methods and mark the wrapper so it is never wrapped twice. Code that touches calibre internals catches exceptions and prints a traceback rather than breaking calibre's startup.

## Building and testing

- `python build.py` writes `lectrix.calibre-palette` and `dist/lectrix-themes.zip` and `dist/lectrix-themes-edit-book.zip`. `dist/` is ignored. Commit the palette file whenever the colors change.
- `python build.py --install` also loads both zips into calibre: it closes calibre if it is open (`calibre-debug -s`, which aborts running jobs), installs them with `calibre-customize -a` and starts calibre again. Run it after every change.
- There are no automated tests. Plugins are checked in calibre: load both zips in Preferences → Plugins → Load plugin from file, restart, and look at both modes, the main window, a few dialogs and the book editor. Don't load a `src/` plugin folder directly (`calibre-customize -b`): it lacks the shared modules.
- calibre's own source is the reference for anything about palettes, `gprefs`, `tprefs` and plugin APIs. A copy is in the neighbouring folder `../calibre`, a shallow clone at the tag of the installed calibre (`calibre-debug --version`). Read it there rather than fetching files from GitHub. The installed calibre ships compiled code only. Its style, `CalibreStyle`, is C++ in `src/calibre/gui2/progress_indicator/CalibreStyle.cpp`. After a calibre update, move the clone to the new tag: `git -C ../calibre fetch --depth 1 origin tag v<version>` then `git -C ../calibre checkout v<version>`.

## Versions and releases

- The version is in two places that must match: `version` in `src/main_plugin/__init__.py` and `src/editor_plugin/__init__.py`. There is no `manifest.json` or `package.json`.
- A release attaches the two zips and `lectrix.calibre-palette`; the README links to `releases/latest` for them.

## Changelog

`CHANGELOG.md`, English only, newest version first. Every user-visible change gets an entry in the same commit, under the next version's heading. Write for calibre users, not developers: say what they see, in the README's plain style. Internal changes (refactors, build tweaks, docs) don't go in.

## Writing style

The README, code comments, docstrings and setting labels share one voice: short, plain sentences, calibre's own names for things (Adjust colors, Look & feel, Edit book, Tag browser), no marketing words. Keep the README's tables in step with the code when behavior or colors change, including the palette mapping table.
